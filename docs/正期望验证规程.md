## 1. 分档门槛（全部满足才算通过该档）

| 档 | 样本 | 通过条件 | 不通过怎么办 |
|---|---|---|---|
| **R1a** 单闸门回放 | n ≥ 20 | 均U > 0 **且** 90%CI 下界 > 0 | 换闸门，不上线 |
| **R1b** 组合配方回放 | n ≥ 10 | 同上 | 放弃该组合（本样本量不支持叠条件） |
| **R2** 实盘小样 | n ≥ 30 | 均U > 0 且 最大回撤 < 25% | 立刻回滚配置 |
| **R3** 实盘确认 | n ≥ 100 | 均U > 0 且 90%CI 下界 > 0 且 最大回撤 < 30% | 回滚 |
| **R4** 加仓 | R3 通过 | 单笔风险 4U → 8U，再验 n ≥ 100 | 任一 30% 回撤即减半 |

> **为什么 R1 要拆两档**：实测 45 笔样本里，能到 **n≥20** 的只有 6 个单闸门变体；
> 而组合类配方只有个位数——「做多 + RR≥1.5」**n=7**、「做多 + RR≥1.5 + 仅 channel」**n=2**。
> 它们**结构上无法通过 n≥20**。不拆档就只能得出「什么都不够格」的假结论。
> （唯一通过 R1b 的是「做多 + 通道/区间」n=14，见 T2。）

### 2.7 ⚠️ R2/R3 的「最大回撤 < 25%」口径问题（待你裁定）

`tools/expectancy_report.py` 里按计划 T3 给的 `max_drawdown()` 算的是
**相对「累计净额峰值」的回撤比值**，不是账户权益回撤：

| 口径 | 73 笔实盘实测（2026-09-18） | 读法 |
|---|---|---|
| 计划口径 `max_drawdown()` | **758.7%** | 回吐了峰值利润（+24.29U）的 7.59 倍 |
| 新增 `max_drawdown_usdt()` | **184.26U** | 峰值到谷底的绝对回撤 |

三个要点：

1. 比值 >100% 是可能的（峰值小、回吐大）⇒「回撤 < 25%」按计划口径读作
   **「回吐峰值利润的 25%」**，不是「账户权益回撤 25%」；
2. 该口径还有盲点：纯亏序列（0 → −1 → −2）返回 **0.0** —— 它在 `peak > 0` 时才记，
   **一直亏却不报回撤**；
3. 现在两种都打印：`回撤184.26U(峰值口径758.7%)`；
   **门槛判定仍按计划口径**（不擅自改 spec），绝对口径只作参照。

**未决问题**：25% 的分母是什么？若要按账户口径，需要一个参照本金。
现有锚点只有 `daily_loss_limit_usdt = 30U`、`risk_per_trade_usdt = 4U`、`max_notional_usdt = 100U`。
**需要指定参照本金**（例如 testnet 账户权益），否则 R2/R3 的百分比门槛无法解释。

**已备好开关**（你给一个本金就能一条命令切口径）：

```bash
.venv/bin/python tools/expectancy_report.py --capital 250
# n=73 ... 回撤184.26U(峰值口径758.7%) 账户回撤73.7%(本金250U) 阶段=R2 -> FAIL

.venv/bin/python tools/expectancy_report.py --capital 250 --account-dd-gate
# 门槛(R2): n>=30, 均>0, CI下界>0, 账户回撤<25%
```

- `--capital U`：**只加输出**，不改判定；账户回撤 = 绝对峰值回撤 ÷ 本金
- `--account-dd-gate`：把 R2/R3 的回撤判定切成账户口径（**必须同时给 `--capital`**，缺则退出码 2）
- 两个都不给 = 计划 T3 原行为，只把门槛行措辞明确为「峰值口径回撤」

以 **250U** 本金试算：账户回撤 **73.7%** ⇒ 两种口径都远超 25%，这一段实盘同样不合格；
但「758.7%」和「73.7%」含义完全不同 —— 前者是"回吐了峰值利润的 7.6 倍"，后者才是风险敞口。

### 2.8 统计功效：计划的门槛只能测出大效应（2026-09-18）

实测单笔净额的标准差（45 天回放）：**σ ≈ 4.91U**（全部 46 笔）/ **4.61U**（过闸门 11 笔）。

要在 `90%CI 下界 > 0` 的前提下确立均值 μ，需要 `n ≈ (1.645·σ/μ)²`：

| 目标 μ（U/笔） | σ=4.91 时所需 n |
|---|---|
| +0.5 | **261** |
| +1.0 | 65 |
| +2.0 | 16 |
| +3.0 | 7 |
| +3.47（本次观测） | 5 |

**把计划的门槛反解成"最小可测效应"（MDE）**：

| 档 | 门槛 | 能测出的最小 μ |
|---|---|---|
| R1b 组合配方 | n≥10 | ≥ **+2.6U/笔** |
| R1a 单闸门 | n≥20 | ≥ **+1.8U/笔** |
| R2 实盘小样 | n≥30 | ≥ **+1.5U/笔** |
| R3 实盘确认 | n≥100 | ≥ **+0.8U/笔** |

**这意味着什么**：

1. 计划的验证协议**只能证明"大效应"**（≥1.5U/笔，即单笔风险的 37% 以上）。
   若真实边际是 +0.5U/笔（1:2 盈亏比、胜率略偏的常态），需要 **230+ 笔** —— 与"60 次分析/天、
   闸门只留 24% 成交"的累积速度**直接矛盾**（那是几百天量级）。
2. 反过来，R1b 的 `n≥10` 之所以能给出 PASS，是因为观测到的 +3.47U 是**异常大的效应**；
   而 §5.1 的对抗检验显示它**不稳**——去掉一个品种就跨零。
3. ⚠️ 功效公式假设样本**独立同分布**。n=11 那组的脆弱**不是**蒙特卡洛噪声造成的，
   而是**聚集**造成的（3 笔是同一波行情）⇒ 有效独立样本 ≈7–8 笔，
   **R1b 的 n≥10 实际比公式显示的还要弱**。

> 结论：**不是"再等等就够"，而是"这个协议在当前样本速率下无法判定一个现实量级的效应"。**
> 要推进，必须先解决样本生产速率（轮询频率 / 挂单成交 / 标的），或把验证目标改成
> "能否排除大亏"而不是"能否证明正期望"。

### 2.9 路 B 开关：证明"不差于 -X U/笔"（2026-09-18）

§2.8 说明当前协议要 261 笔才能测出 +0.5U/笔 的现实边际。
**换一个可验证的问题**能大幅降低样本需求：证明均值**不差于 -X U/笔**（排除大亏）。

```bash
.venv/bin/python tools/expectancy_report.py --loss-bound 2          # 排除"均亏损>2U/笔"
.venv/bin/python tools/expectancy_report.py --gate-since --loss-bound 2   # 只看上线后样本
```

判据：`90%CI 下界 > -X` ⇒ 可排除。给了 `--loss-bound` 就以它决定退出码（R2/R3 那套仍会照常打印）。

**为什么样本少那么多**：要确立 +0.5U/笔 需 261 笔；而排除 -2U/笔 只需 **约 16 笔**（真值≈0 时）。
n<30（"样本不足"）时它同样给结论 —— **这正是它的用途**。

实测（2026-09-18，全部 73 笔历史样本）：

```text

n=73 均-2.19U 胜率37% 90%CI[-4.66, +0.11] 回撤184.26U(峰值口径758.7%) 阶段=R2 -> FAIL
门槛(R2): n>=30, 均>0, CI下界>0, 峰值口径回撤<25%
路B判定: 90%CI 下界 -4.66U <= -2.00U => 无法排除 均亏损大于 2.00U/笔 (n=73)
```

⇒ 连"不差于 -2U/笔"都排除不了 —— 这是对历史样本的又一个直白结论。
