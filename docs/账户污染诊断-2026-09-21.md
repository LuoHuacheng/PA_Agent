# 账户污染诊断: 90% 的亏损是两笔违规单 (2026-09-21)

> 承接 [归因覆盖率与账户真相](./归因覆盖率与账户真相-2026-09-21.md). 那篇查明 30 天账户
> 实现 -1963.64U, 而策略范围只有 -258.89U. 本篇回答: 那多出来的钱是谁亏的.

## 1. 判据 (两条, 任一命中即标记)

单看"品种不在白名单"不够 —— 更硬的判据是**名义仓位超过配置上限**:

1. `unanalyzed_symbol` —— 该品种在 `records/pending/` 里从未出现, 即管道从没做过决策;
2. `oversized_notional` —— 单笔名义超过 `max_notional_usdt * leverage`.

配置: `max_notional_usdt = 250`, `leverage = 20` -> 上限 **5,000U**.

## 2. 结果 (`tools/account_contamination.py --days 30`)

| 分组 | 腿数 | 净额 |
| --- | --- | --- |
| 策略可能产生 | 841 | -172.30U |
| **策略不可能产生** | **76** | **-1893.57U** |
| 账户合计 | 917 | -2065.88U |

按判据: `oversized_notional` 2 条 **-1850.86U**; `unanalyzed_symbol` 75 条 -1726.63U.

**两笔超标单就占账户全部亏损的 90%**:

| 品种 | 名义 | 净额 | 判据 |
| --- | --- | --- | --- |
| HEMIUSDT | 29,369.77U | -1683.91U | 未分析 + 超标 (5.9x) |
| **BTCUSDT** | **18,127.29U** | **-166.94U** | 超标 (3.6x) |

(BTCUSDT 这笔在策略品种里, 只有名义判据能抓到 —— 它解释了早先"账户 BTC -188.26U vs
outcomes -13.84U"那个缺口的大半.)

其余按品种: SKRUSDT -24.21U / LTCUSDT -23.26U / AKEUSDT -11.85U / 牛来USDT -7.42U /
AVAXUSDT -2.10U / ... / BTRUSDT +26.61U.

## 3. HEMIUSDT 的完整证据链

2026-08-31 16:58:47 一笔 `BUY 1,779,986 HEMIUSDT @ 0.0165` = **29,369.77U 名义**,
37 分 38 秒后 (17:36:25) 全部平掉, 实现 -1654.18U + 手续费 -13.85U.

五条证据说明它不可能是 PA_Agent 下的:

1. `records/pending/` **全历史零个 HEMIUSDT 文件**(5797 个记录, 品种池 11 个, 不含它)
   -> 模型从未分析过它, 更不可能对它下单;
2. 名义 29,370U = 配置上限 5,000U 的 **5.9 倍**;
3. 该持仓杠杆 **10x**, 而配置是 20x;
4. 不在监控标的/白名单里 (当时是 BTC/ETH/SOL/ZEC/XRP, 全 15m);
5. `/fapi/v1/allOrders` 对该品种返回 **0 条** -> 没有经过执行层那条下单路径留下的痕迹.

同一账户 08-20 还有两笔小额 HEMIUSDT (9,085 / 6,056 数量级) —— 说明这个品种在 08 月就被人
在这个账户上手动玩过.

## 4. 结论

1. **账户亏损的 90% 是两笔违反名义上限的持仓**, 外加一批从未被策略分析过的品种.
   这不是策略的表现, 是**账户被污染**.
2. **策略自身在 30 天里是 -172.30U / 841 条腿**, 与 outcomes.csv 的 -167.84U 量级一致
   (差 2.7%) —— 这是账户口径与归因口径第一次互相印证. outcomes.csv 虽然只覆盖账户
   损益的 8%, 但它覆盖了**策略损益的绝大部分**.
3. 之前报告里"策略外 -1704.75U"这个数被两笔违规单主导, 不应该读成"策略外的交易在亏钱".

## 5. 建议

1. 把 `tools/account_contamination.py` 纳入例行检查: 任何"账户亏了多少"的结论, 先跑一遍
   污染诊断再引用.
2. 查那两笔是谁下的. 本地日志里**没有**痕迹(08-31 那天 `logs/` 无相关记录, 本地订单账本
   09-18 才开始记), 需要人工确认: 是不是手工在 testnet 网页端开的, 或者密钥被别处用过.
3. 在查清之前, 这个账户的账户级盈亏不能用来评价策略; 要评就评**策略范围**(第 2 节第一行).
4. 可考虑把污染汇总接进 `tools/outcome_merge.py` 的覆盖率报告, 让"账户真相"自带
   "其中多少不可能来自策略"这一行.
