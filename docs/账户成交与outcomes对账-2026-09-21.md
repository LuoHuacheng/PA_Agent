# 账户成交 vs outcomes.csv 对账 (2026-09-21)

> 起因: 上一轮报告留下一个未解释的缺口 —— 账户成交重建 (5 品种, 2026-09-15 -> 09-21)
> 是 **16 笔 +33.93U**, 而 `trade_records/outcomes.csv` (2026-09-04 -> 09-21) 是
> **102 笔 -167.84U**. 方向相反, 无法同时成立. 本文把它对完.

## 1. 方法

三层口径:

1. **income 流水** (`/fapi/v1/income`) —— 账户真相. 只取 `REALIZED_PNL` / `COMMISSION` /
   `FUNDING_FEE` 三类汇总.
2. **userTrades 重建** —— 用 `pa_agent.trading.replay_pairing.rebuild_trades` 按品种 LIFO
   配对成交易腿, 取 `realized + fees`.
3. **outcomes.csv** —— 策略归因结果.

窗口 30 天 (2026-08-23 -> 09-22), 覆盖 outcomes.csv 的全部 102 行.
品种集合并集: 配置白名单 + income 流水里出现的品种 + outcomes.csv 里的品种 = 21 个.

## 3. 三个结论

### 3.1 outcomes.csv 只覆盖账户损益的 8%

账户 30 天实现 -2052.13U; outcomes.csv 只有 -167.84U, 覆盖率 **8.2%**.
`record_file` 归因能 join 上 102 笔, 而账户里有 **917 条交易腿**.

### 3.2 一半以上的亏损来自策略根本没碰的品种

11 个品种有账户盈亏但没有 outcomes 行, 合计 **-1712.70U**, 占账户总亏损的 83%:

| 品种 | 盈亏 |
| --- | --- |
| HEMIUSDT | **-1683.91** |
| LTCUSDT | -23.31 |
| SKRUSDT | -17.25 |
| AKEUSDT | -11.81 |
| 牛来USDT | -7.42 |
| 其余 6 个 | +30.99 |

**HEMIUSDT 一个品种吃掉账户全部亏损的 82%**, 而它只有 13 条 income 记录 / 1 笔交易 ——
-1683.91U 集中在单笔上. 它不出现在 `records/pending/*.json`, 也不在监控品种里.
另外 `牛来USDT` 这种名字不像是真实的合约标的.

### 3.3 即使策略品种也对不上

BTCUSDT: 账户 **-188.26U** vs outcomes **-13.84U** (6 笔). 差 174U.
LTCUSDT / SKRUSDT / AKEUSDT / AVAXUSDT / BCHUSDT 等完全不在 outcomes.csv 里.

## 4. 对既有结论的影响

1. **上一轮那个 "16 笔 +33.93U" 不能用**. 它是 5 个配置品种 × 6 天的切片, 天然排除了
   HEMIUSDT 那 -1683.91U, 所以符号为正. 它不是账户真相, 只是一个子集.
2. **outcomes.csv 是"归因到的子集", 不是账户真相**. 任何拿它当标的的研究只看到 8% 的
   账户损益 —— 包括本会话早先的"真实结局因子审计" (n=90/102), 以及执行层所有
   `sim_trailing_stop.py` 的配对结论.
3. **重建与 income 在主要品种上是对的**: BTC/ETH/SOL/XRP/ZEC/ADA/DOGE/LINK 的差都
   < 0.5U. 只有小样本品种对不上 (SKRUSDT -6.96, 1000PEPEUSDT -5.07, ONGUSDT -1.99) ——
   LIFO 配对在只有 1-2 笔的品种上会错配. 所以重建管线本身没问题, 问题在口径覆盖.
4. 窗口边界注意: income 只统计窗口内的平仓流水; 跨窗口的持仓会在窗口内一次性实现.

## 5. 建议

1. **账户级真相一律用 income 流水**, 不再用"重建成交"当账户损益.
2. **outcomes.csv 应显式标注为归因子集**, 并在报告里同时给出覆盖率 (当前 8%).
3. **查 HEMIUSDT / 牛来USDT 的来源**: 谁开的、什么时候、为什么不在 pending 记录里.
   在查清之前, 该账户的任何"策略盈亏"结论都站不住.
4. 归因率本身是个可优化指标: 917 条腿只归因 102 条 (11%), 提高它才能让 outcomes.csv
   有意义.
