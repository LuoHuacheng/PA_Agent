## 2. 为什么干跑期"等不到"样本

两条硬事实（代码位置）：

1. `dry_run=true` 时 `execute_market_signal` 立即 return，不发任何 API
   （`pa_agent/trading/binance_usdm_testnet.py:1111`），`_execute_breakout_signal` 同理（`:1462`）。
2. `_resume_guards` / limit watcher 在干跑下不被拉起（`:2733`、`position_manager.py:1334`）。

**实测佐证（2026-09-19 19:07 现场）**：10:12 打开 dry_run 后，115 条决策全部
`类型=不下单` 的是模型自己观望；但 09-18 20:14~09-19 10:12 之间那 20 条
`类型=限价单` 的入场意图，**一条都没落成挂单**（`status=dry_run` 分支在
`signal_pipeline._execute` 只在 info 级落日志，`grep` 干净也算正常 —— 判据看
`records/orders/` 是否有新增行，不看日志）。

推论：**保护链路（guard / watchdog / TP runner / 补挂 / swap / 告警）在干跑期零覆盖。**
9-19 修的 3 个 commit 也一行没跑过。干跑不是"安全的观察期"，是"没有观察对象的空转期"。
