# 被拦订单反事实分析（2026-09-20）

**问题**：所有被拦截的订单，如果成交，盈亏如何？

- **样本**：`records/pending/` 45 天，796 条可回放计划单（限价单/突破单）；其中 **160 条被拦**
- **拦截事实来源**：`stage2_decision.execution`（`status` + `gate_reasons`），见 `pa_agent/records/execution_marker.py`
- **区间口径**：`bootstrap_mean_ci`，20000 次自助重采样，`alpha=0.10`，`seed=7`
- **复跑**：`PYTHONPATH=. .venv/bin/python scripts/_blocked_orders_ci.py [--detail]`
- **回放参数 = 线上现值**：`risk 4U`、`leverage 20`、`margin 250U`、`partial 50%`、`timeout 120min`、`time-stop 720min`、`min-stop 0.2%/1.2ATR`

## 1. 两个反事实口径

| 口径 | 含义 |
|---|---|
| **A 按原计划挂单** | 只有价格回踩到 entry 才成交（与线上挂单行为一致）；未触及记 0，所以净额只反映那几笔真会成交的 |
| **B 决策时市价入场** | 假设立刻以决策时刻收盘价进场、结构止损/止盈不变。回答"这些机会本身值多少钱"，不被"回踩没到"稀释 |

两个口径对**放行组用同一算法**，所以组间可比。

## 2. 被拦订单构成（160 条）

| status | 条数 | 说明 |
|---|---|---|
| `gate_blocked` | 64 | 入口门控拦截，**带 gate_reasons** |
| `rejected` | 89 | 执行层拒绝，**原因未落盘**（见 §5） |
| `skipped` | 7 | 置信度低于阈值等 |

可归因的 64 条拦因分布：`trending_tr_block` 26、`session_block` 20、`rr_block` 11、`cycle_block` 9、
`neutral_diag_block` 6、`short_block` 4、`G1 close-touch` 1。

## 3. 如果成交：整体是赚的

| 口径 | n | 成交 | 胜 | 净U | 均U | 90%CI |
|---|---|---|---|---|---|---|
| **A 按原计划挂单** | 160 | 17 | 11/17 | **+59.37** | +0.37 | **[+0.11, +0.65]** |
| **B 决策时市价入场** | 160 | 77 | 54/77 | **+57.67** | +0.36 | **[+0.13, +0.60]** |

两个口径都给出**全正区间**：这批被拦的计划单本身是正期望的，规模约 **+58U / 45 天**（回放口径）。

## 4. ⚠️ 但和放行组比，分不出高低

第一次对照显示"被拦明显好于放行"（+0.36 vs −0.14），**但那是时间混杂**——
被拦记录集中在 09-13 之后，放行组大半是 08-07~09-12 的早期样本。按时间分层后：

| 分段 | 口径 A n / 均U / CI | 口径 B n / 均U / CI |
|---|---|---|
| 早期（<09-13）被拦 | 0 | 0 |
| 早期（<09-13）放行 | 502 / −0.09 / [−0.27,+0.10] | 502 / −0.23 / [−0.39,**−0.06**] |
| **闸门期 被拦** | 160 / **+0.37** / [+0.11,+0.65] | 160 / **+0.36** / [+0.13,+0.60] |
| **闸门期 放行** | 134 / +0.31 / [−0.10,+0.75] | 134 / +0.16 / [−0.20,+0.52] |

⇒ 同一时间窗内，被拦组与放行组的均值差（+0.06 / +0.20U/笔）**CI 大幅重叠**，
**闸门栈在期望维度上没有可确立的区分能力**：它把样本量砍到 1/4，却没有换来更高的期望。
（早期放行组的口径 B 区间 [−0.39,−0.06] 全负，说明 09-13 前那套配置确实是负期望——
闸门出现的背景成立；但它现在的边际贡献无法用这批数据证明。）

| 拦因 | 口径 A | 口径 B | 判断 |

| `session_block` | 0 笔成交（挂单从不成交） | 7 笔成交 **+10.71**，7/7 全胜，[+0.29,+1.11] | 表面"拦错了"，但见下 |

**`session_block` 的"拦错"经不起看**：16 条被拦单里口径 A 成交 **0 笔**（挂单价离市价远、

09-19 04:00~06:02 LINK/ETH 做多 4 笔）。按禁令 2（同批样本、近似重复），**有效独立样本 ≤ 2~3 波**，
不构成放开它的依据。

## 6. 三个可执行发现

1. **可观测性缺口（最大盲区）——已修（2026-09-20 15:18）**：89 条 `rejected` 只落了 `status`，
   **没落原因**——`mark_execution(decision, status=result.status)` 丢掉了 `ExecutionResult.reason`
   （`signal_pipeline.py:389`）。这批恰好贡献了绝大部分净额，等于最值钱的那部分拦单无法复盘。

   **修复**：`mark_execution` 新增 `reason` 参数（与门控的 `gate_reasons` 互补，空值省略该键），
   `signal_pipeline` 的执行结果分支传入 `ExecutionResult.reason`。

   | 项 | 值 |
   |---|---|
   | 改动 | `pa_agent/records/execution_marker.py`（新增 reason 字段）、`pa_agent/trading/signal_pipeline.py:389`（传入 reason） |
   | 测试 | 新增 `tests/unit/test_execution_marker.py`（5 例） |
   | 生效 | SIGTERM pid 55155 → **pid 56596**，2026-09-20 15:18:19，下一轮 16:00:05 |
   | `GATE_START` | **不前移** —— 纯观测字段，不参与任何下单/拦截判定，配置与策略未变 |
   | 归因脚本 | `scripts/_blocked_orders_ci.py` 已优先读 `reason`（历史记录无此键时退回「记录未存原因」） |

   效果从**下一批**被拒单开始可见；本节那 96 条的历史原因**已无法追溯**。
2. **`trending_tr_block` 是全闸门栈里唯一被两个口径一致支持的**（A −0.96 / B −6.77）。
   这也解释了为什么 09-20 00:51 的"放行 trending_tr"在 09-20 14:09 就被回滚。
3. **闸门栈的边际贡献无法用样本内数据证明**：被拦≈放行（CI 重叠）。
   要判定它有没有用，只能等上线后的样本外窗口（路 B，n≥16）。

## 7. 边界与警告（必须一起读）

- **回放偏乐观约 2U/笔**、结局类型判错约 1/3（`docs/正期望验证规程.md` §2.10）⇒
  §3 的 **+58U 绝对量级要打折**；组间比较（§4/§5）受影响较小。
- 口径 B 是**反事实**：线上是挂单策略，市价入场只是为看清"机会本身"，
  **不能据此直接改成市价开仓**。
- 被拦集合随配置变化（`block_*` 开关改过 4 次），所以这 160 条不是同一个策略下的样本。
- 早期放行组含 `execution` 未标记的历史记录（标记功能 09-13 才接入），
  §4 的"放行"组因此混有"根本没走到执行层"的记录。
