# 回撤门槛本金口径裁定（2026-09-20）

## 裁定

| 项 | 值 |
|---|---|
| 参照本金 | **账户现有余额**（每次动态读取 `totalWalletBalance`） |
| 当下余额 | **4809.59 U**（Binance U 本位 Testnet，2026-09-20 18:57 实测） |
| R2/R3 回撤门槛 | **切账户口径**（`--account-dd-gate`） |

背景与未决问题的由来见 `docs/正期望验证规程.md` §2.7。

## 为什么要切

`tools/expectancy_report.py` 原实现 `max_drawdown()` 的分母是**累计净额的峰值利润**，不是账户权益：

```python
peak = max(peak, equity)
if peak > 0:                      # 只在有过正峰值时才记回撤
    worst = max(worst, (peak - equity) / peak)
```

两个后果：

1. 比值可以 >100%（实盘 73 笔给 758.7%，因为峰值只有 +24.29U，回吐 184.26U）；
2. **纯亏序列返回 0.0** —— 一路亏却不报回撤，这一条会误判为通过。

账户口径 = `max_drawdown_usdt() / 本金`，才是「亏了本金的百分之几」这种风险语言。

## 当前数字（n=98）

```text
回撤235.48U(峰值口径969.6%) 账户回撤4.9%(本金4810U) 阶段=R2 -> FAIL
```

| 口径 | 值 | 读法 |
|---|---|---|
| 峰值口径 | **969.6%** | 回吐了峰值利润的 9.7 倍 |
| 账户口径 | **4.9%** | 亏掉本金的 4.9% |
| 门槛（R2） | < 25% | 账户口径**通过**；峰值口径严重超标 |

⚠️ **两种口径下这一行都是 FAIL** —— 因为 `均>0` 与 `CI下界>0` 两条同时不满足，
回撤只是四条判据之一。切口径**没有改变任何已有结论**，只是让回撤那一行可解释。

## 落地

两个日检入口都改为**每次动态读余额**再判定：

| 文件 | 改动 |
|---|---|
| `scripts/daily_check.py` | 新增 `account_equity()`；四条 `expectancy_report` 调用带 `--capital <余额> --account-dd-gate`；台账增 `权益:` 列；输出增第 9 行 |
| `scripts/daily_check.sh` | 等价改动（遗留手工入口） |

**失败回退**：取余额失败（网络/密钥/权限）时 `equity=None`，此时**退回计划口径**
（只打印峰值口径回撤、不切门槛），日检绝不因取余额失败而中断。

## 边界

- 本金是**动态**的：余额变化会改变同一个绝对回撤对应的百分比。跨日比较回撤时
  必须连同本金一起记（台账已有 `权益:` 列）。
- 门槛从峰值口径切到账户口径，属于**判定口径变更**。既有窗口的结论不受影响
  （两种口径都 FAIL），但今后引用「回撤 < 25%」时必须说明是哪种口径。
- 峰值口径函数保留不动（仍会打印），便于回看历史。
