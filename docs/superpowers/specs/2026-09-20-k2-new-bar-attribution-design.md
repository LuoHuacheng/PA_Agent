# 「K2 纳入依据」量化设计（预注册）

**日期**：2026-09-20
**状态**：设计已确认（用户批准 L0 → L1 路线），本文档的**判定规则在跑数前冻结**
**关联提交**：`b805207 🐛 fix(monitor): 增量分析改同基数新棒并如实上报每小时 2 根`

---

## 1. 要回答的问题

修复前，监控增量提示词把「新增已收盘K线」恒报为 **1**（伪时间戳 +8h 与真实 epoch 混算 → 差值恒负 → `max(1, …)` 夹成常量），而实际每轮进 **2** 根 30m 棒；模型被硬规则强制 `new_closed_bars=["K1"]`。

**待测问题**：`K2 被显式标注为"新增"并允许进入增量依据` 这件事，是否改变模型决策、并进而改变影子回放的结局？

## 2. 目标 / 非目标

**目标**
- 量化「K2 标注修复」对 ①决策 ②影子结局 的影响，并给出 90% 置信区间与 MDE。
- 允许并接受 **null 结论**（测不出影响），此时报告"可探测的最小效应"。

**非目标**
- 不预测"胜率会提升多少"；不做生产代码改动；不评估换 1h 周期（另案）。
- 不把"净U 变好"当作唯一结论 —— 必须同时给 gross / fees 拆解（上一轮 1h ATR 实验的教训：净额变好可能全部来自仓位缩小省下的手续费）。

## 3. 方法论约束（为什么只能离线重跑）

处理是**恒定**的：`近 24h 180/180 轮 = 2 根新棒`，而程序一律声称 1 根。
⇒ 处理组无变异、无对照 ⇒ **事后相关性无法识别效应**。

记录里存有完整 `stage1_messages` + `kline_data` + `previous_record`（上一条记录），因此可对同一次决策时刻做**冻结输入的离线重跑**。

## 4. 三阶段设计

### Phase 0 —— 零 LLM 成本门控（L0）

**假设**：若模型本来就对"有信息量的 K2"有反应（因为 60 根全表里 K2 始终在场），则标注缺失的代价≈0，不必花钱做 A/B。

**做法**（全本地计算，只读 `records/pending`）
- 样本：白名单 30m 目标、走增量路径（`stage1_diagnosis.incremental_delta` 存在）、与前一条记录**连续**（锚点仍在窗口内、且新棒数=2）。
- 自变量 K2 材料性（`K1`=最新已收盘棒，`K2`=次新 = 未被标注的那根），**主指标**：`|K2.close-K2.open| / ATR14 ≥ 0.5`；
  稳健性指标：K2 突破前 20 根高点/低点、K2 与 K1 反向、K2 为 outside bar。
- 因变量（相对上一轮）：`direction` 变化、`cycle_position` 变化、`trade_confidence` 变化、本轮是否出计划、计划是否实质变化。

**预注册判定（冻结）**

| 结果 | 判定 | 行动 |
|---|---|---|
| 材料K2 反应率 − 非材料K2 反应率 **≥ 15pp**（direction 变化率口径） | 模型已在用 K2 | **只跑 L1 确认**（不扩到 L2） |
| 差值 **< 15pp** | 存在"K2 被系统性忽略"迹象 | 值得跑 L1，视 CI 决定是否上 L2 |

Phase 0 **不是证据**（存在混淆），只是决定要不要花钱的闸门。

### Phase 1 —— 配对 A/B（L1 = 24 轮 / 48 次调用）

| | A 臂（对照） | B 臂（处理） |
|---|---|---|
| 新棒标注 | 1 根 | 2 根 |
| 决策来源 | 记录中的 `stage2_decision`（须通过可复现校验） | 现场重跑 |
| 输入 | 同一 `kline_data` + 同一 `previous_record` | 逐字节相同 |

- **可复现校验（保真闸门）**：用当前 prompt 文件渲染 A 臂 stage1 用户消息，与记录里 `stage1_messages` 做字节 diff；不一致的轮次剔除。通过率 <80% ⇒ 退化为"直接编辑 stored messages 的新增块"方案。
- 复用件：`PromptAssembler.can_build_incremental_stage1()` / `build_incremental_stage1()`、`demo.record_loader.frame_from_record_klines()`、`ai.client_factory.create_ai_client()`、`ai.json_validator.JsonValidator`。
- **噪声地板臂**：随机 10% 轮次把 A 臂再跑 2 次，量同输入抖动。**没有它，任何 A↔B 差异都不可解释。**
- 采样：按时间倒序取最近的连续轮次，覆盖多品种；同一品种在窗口内尽量均匀。

### Phase 2 —— 影子结局（0 额外调用）

两臂决策 → `shadow_replay.Plan` → 同一条 timeline 跑 `simulate_plan()`，参数锁定生产值：
`timeout_min=120, time_stop_min=720, min_stop_atr=1.5, min_stop_pct=0.2, partial_pct=50, risk_usdt=4, maker=0.0002, taker=0.0004`。

**指标（逐轮配对）**
1. 计划变更率（主，决策层）：order_type/direction/entry/stop/tp 任一实质变化，或 `trade_confidence` 跨档。
2. 方向翻转率、`trade_confidence` 配对均值差。
3. 影子净U 差（配对）+ bootstrap 90%CI；成交率、胜率、每笔期望。
4. gross / fees 拆解。
5. 操纵检查：B 臂 `new_closed_bars==["K1","K2"]` 比例、summary/trace 提及 K2 比例。

**预注册判定规则（冻结，事后不改）**

> 仅当 **①计划变更率 > 噪声地板臂上界** 且 **②配对净U 差的 90%CI 不跨 0** ⇒ 判定"实质影响"；
> 否则结论为 **null**，并报告 MDE。
> 任何情况下都要给 gross/fees 拆解；禁止只用净U 下结论。

## 5. 成本阶梯

每轮 = stage1+stage2 = 2 次调用；实测均值 **153k prompt / 17k completion** token/轮；5 品种 × 24 = **120 轮/天**。

| 档 | 轮数 | 调用 | 说明 |
|---|---|---|---|
| L0 | 0 | 0 | Phase 0 门控 |
| L1 | 24 | 48（+噪声地板 ≈ +10） | 链路打通 + 抖动基线 |
| L2 | 120 | 240 | 主试验 |
| L3 | 240 | 480 | CI 过宽时加密 |

成本坑：① 两臂的"新增块"之前前缀相同、之后不同 ⇒ B 臂 cache hit 低于生产；② 噪声地板臂额外 +20%。

## 6. 风险与边界

| 风险 | 处理 |
|---|---|
| prompt 版本漂移 | Phase 1 的可复现校验；不过则剔除或退化为编辑方案 |
| 模型非确定性 | 噪声地板臂；判定规则用其作为阈值 |
| 样本量 | L1 只做链路+抖动；主结论必须 L2 起；一律给 CI 与 MDE |
| 模拟器假设（同根 SL 优先、不建保本移损、成交当根不利用剩余振幅、跳空按开盘价） | 报告里明示；两臂同参数，配对比较不受此偏差影响 |
| 把费用效应误读成策略效应 | 强制 gross/fees 拆解 |

| 日期 | 阶段 | 结果 | 判定 |
|---|---|---|---|
| 2026-09-20 | Phase 0 (L0) | 297 配对轮次；主指标 31.7% vs 31.1% ⇒ **+0.6pp**；稳健性：破前高低 **−6.3pp**、与 K1 反向 **−12.0pp**、outside +0.4pp；计划实质变化率 97.2%（70/72） | **worth_ab**（<15pp）⇒ 按预注册进入 L1 |

### 7.1 Phase 0 结果解读（诚实边界）

- 主指标上"材料 K2"与"非材料 K2"的 direction 变化率几乎相同；两个稳健性指标甚至**反向**（材料 K2 反应率更低），说明该因变量受状态混淆（趋势/安静态下诊断更稳定）。Phase 0 **不构成证据**，只用于触发 L1。
- 计划实质变化率 97.2% 提示：该指标在 L1 可能**贴天花板**，配对比较可能直接得到 null —— 这是可接受的结论，噪声地板臂会给出上界。
