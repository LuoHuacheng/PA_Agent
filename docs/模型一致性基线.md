# 模型一致性基线 (variance baseline)

日期：2026-09-10　模型：DeepSeek-V4-Flash-0731 (thinking=True, effort=high)
工具：tools/variance_baseline.py (单条多次), tools/variance_batch.py (批量)

## 1. 为什么要做

此前所有归因（周期位置盈亏、置信度校准、方向命中率）都隐含一个假设：
**同一份 K 线，模型给出的标签是稳定的**。如果模型自己都会给出不同答案，
建立在这些标签上的过滤与结论都要打折。

## 2. 方法

    # 单条: 同一记录跑 5 次, 打印逐次答案与一致率
    python tools/variance_baseline.py <文件名> 5 trimmed

    # 批量: 多条记录各跑 5 次, 用后续真实 K 线判定命中率, 比较单次 vs 投票
    python tools/variance_batch.py --count 20 --runs 5 --per-symbol 4 --days 45

trimmed 变体与生产配置一致（prompt_assembler.py:753-771 已核对）。

## 3. 结果：32 条记录 x 5 次

    指标              5/5 完全一致   比例
    direction         30/32          94%
    cycle_position    19/32          59%

    5 次全 neutral 的记录: 8/32 = 25%

两条个案（09-10 09:09 的 BTCUSDT / XRPUSDT）当时分别拿到 80% / 60% 的
direction 一致率，但放到 32 条里看，它们属于 6% 的少数派。

## 4. 周期位置漂移的模式

不稳的记录几乎都在相邻类别之间摇摆，例如：

    2026-09-09_17-09-10_ETHUSDT   [broad_channel, normal_channel, broad_channel, ...]
    2026-09-10_05-09-14_XRPUSDT   [trending_tr, trading_range, broad_channel, trading_range, ...]
    2026-09-10_06-09-48_BTCUSDT   [broad_channel, trading_range, broad_channel, trending_tr, ...]

这与 cycle_candidates.py 把周期位置当**连续谱**的设计吻合：相邻类别本就重叠，
prompt 里也要求"trending_tr 与 normal_channel 特征重叠时降置信"。

## 5. 多数投票有没有用

    direction 完全一致: 16/18
    单次(第1次)      命中  7/ 8 = 87.5%
    多数投票         命中  8/ 9 = 88.9%
    投票 - 单次: +1.4 个百分点

**结论：不值得。** 两个理由：

1. direction 本来就有 94% 的 5/5 一致率，投票能改变的样本只有 6%，而本次
   可用样本仅 8 到 9 条，+1.4pp 完全落在噪声内。
2. 本批命中率 87.5% 不具备代表性 —— 样本集中在 09-09 到 09-10 两天，18 条里
   有 14 条同向（多数看空且真的下跌），是同一波行情的多个切片，不是独立观测。

生产上跑多次采样要把 token 成本翻三倍（约 $22/天 -> $66/天），换来的东西
在当前证据下是零。

## 6. 哪些结论可靠、哪些不可靠

**受噪声影响的（依赖 cycle_position）：**

- "trending_tr 亏 83%" —— 标签 41% 会漂移，该归因被稀释，不能据此禁用某一档
- "只做 normal_channel + 顺势" —— 依赖最不稳的标签，不可作为策略依据
- 周期位置 x 方向的多维切分 —— 每格样本少，再叠 41% 标签噪声

**不受影响的（不依赖 cycle_position）：**

- **禁逆势 (counter_trend_block)** —— 趋势完全由日线 close 算出（确定性），
  方向稳定性 94%，是这一轮里最稳的一条规则。
- 保护单存活校验、仓位口径、日度亏损熔断、手续费 —— 全在执行层
- "系统整体负期望" —— 真金白银的统计

## 7. 约束为什么没兜住

程序侧有候选集机制 (cycle_candidates.score_cycle)，但它是**软约束**：

    prompt_assembler.py:1333   只把候选块渲染进 prompt 供参考
    coherence_checks.py:431    只在输出后做一致性检查

没有任何地方对"模型输出越出候选集"做拒绝或重试。而 constrain_worthy()
要求 top score >= 60 且明显领先，模糊市场里不触发（注释自述：ambiguous
markets produce an empty set and no constraint at all）。

**但注意：执行层 (pa_agent/trading/) 完全不使用 cycle_position**（0 处引用）。
所以即便把标签做准，也不会改变任何一笔交易的去留 —— 这是"研究数据质量"
的改善，不是"盈亏"的改善。优先级低。

## 8. 复现与注意

    python tools/variance_baseline.py <records/pending 下的文件名> 5 trimmed
    python tools/variance_batch.py --count 20 --runs 5 --per-symbol 4 --days 45

- 采样必须**不过滤方向**。只挑"当时方向明确"的记录等于先把高方差的模糊场景
  剔掉，会让结论天然偏向"投票没用"（本工具早期的默认行为，已改为按"是否有
  后续 K 线可判定"筛选）。
- 30m 的 pending K 线覆盖只有 2 到 6 天，样本天然集中在少数几波行情，
  命中率类指标不可外推。
- 运行期间多次出现 503 platform_busy（重试后成功），provider 端不稳定本身
  也贡献方差，解读时别把它算成模型随机性。
