# 模型一致性基线 (variance baseline)

日期：2026-09-10　模型：DeepSeek-V4-Flash-0731 (thinking=True, effort=high)
工具：tools/variance_baseline.py　变体：trimmed (与生产 prompt 文件列表一致)

## 1. 为什么要做

此前所有归因（周期位置盈亏、置信度校准、方向命中率）都隐含一个假设：
**同一份 K 线，模型给出的标签是稳定的**。如果模型自己都会给出不同答案，
那建立在这些标签上的过滤与结论都要打折。

本测试对**同一条记录跑 5 次**，统计 cycle_position / direction / gate_trace
的众数一致率。

    python tools/variance_baseline.py 2026-09-10_09-09-09_BTCUSDT_30m.json 5 trimmed
    python tools/variance_baseline.py 2026-09-10_09-09-52_XRPUSDT_30m.json 5 trimmed

（trimmed 变体与生产配置一致：COMMON 用 提示词大纲 + 二元决策_阶段一闸门；
TASK 用 市场诊断框架 + 文件16。已核对 prompt_assembler.py:753-771。）

## 2. 结果

BTCUSDT 2026-09-10 09:09 (30m)：

    run1  cycle=trading_range  dir=neutral   mp=stable
    run2  cycle=trending_tr    dir=neutral   mp=stable
    run3  cycle=trading_range  dir=neutral   mp=stable
    run4  cycle=broad_channel  dir=bearish   mp=stable
    run5  cycle=trading_range  dir=neutral   mp=stable
    cycle_position 3/5 = 60%    direction 4/5 = 80%
    gate_trace 34/40 = 85%      combined 41/50 = 82%

XRPUSDT 2026-09-10 09:09 (30m)：

    run1  cycle=trending_tr    dir=bearish   mp=stable
    run2  cycle=trending_tr    dir=bearish   mp=stable
    run3  cycle=trending_tr    dir=neutral   mp=transitioning
    run4  cycle=trading_range  dir=bearish   mp=transitioning
    run5  cycle=broad_channel  dir=neutral   mp=transitioning
    cycle_position 3/5 = 60%    direction 3/5 = 60%
    gate_trace 36/40 = 90%      combined 42/50 = 84%

合并：

    指标               BTCUSDT   XRPUSDT   合计
    cycle_position     60%       60%       6/10 = 60%
    direction          80%       60%       7/10 = 70%
    gate_trace         85%       90%       70/80 = 87.5%
    combined           82%       84%       83/100 = 83%

两条记录在 cycle_position 上完全一致地落在 **60%**，不是偶发。

## 3. 解读

- 前置闸门 (1.1/1.2/1.4) 稳定在 5/5，说明"是否进入分析流程"这类判断可靠。
- 不稳的是分类闸门：2.1(区间类型) 3/5、2.3 3/5、2.5 3/5。它们决定的正是
  trending_tr / trading_range / broad_channel 之间的取舍。
- 这与代码里的自述吻合：cycle_candidates.py 把周期位置当**连续谱**，
  相邻类别本来就重叠；prompt 里要求"trending_tr 与 normal_channel 特征重叠时
  降置信到 50-69"。
- direction 70% 意味着：同一份 K 线两次分析，有一次会给出不同方向。
  直接影响"这一轮要不要下单"。

## 4. 约束为什么没兜住

程序侧确实有候选集机制 (cycle_candidates.score_cycle)，但它目前是**软约束**：

    prompt_assembler.py:1333  把候选块渲染进 prompt，供模型参考
    coherence_checks.py:431   只在阶段一输出后做一致性检查

没有任何地方对"模型输出越出候选集"做拒绝或重试。而 constrain_worthy()
要求 top score >= 60 且明显领先，模糊市场里根本不触发。

## 5. 哪些结论仍然可靠

**受噪声影响的（依赖 cycle_position 标签）：**

- "trending_tr 亏 83%" —— 标签 40% 会漂移，该归因被稀释，不能据此禁用某一档
- "只做 normal_channel + 顺势" —— 依赖最不稳的那一档标签，不可作为策略依据
- 周期位置 x 方向的多维切分 —— 每格样本本就不多，再叠 40% 标签噪声

**不受影响的（不依赖模型标签）：**

- **禁逆势 (counter_trend_block)** —— 只用日线 close 算的涨跌幅（确定性）
  加上模型方向。方向的一致性 70% 高于周期位置的 60%，且趋势判定完全是程序算的。
- 保护单存活校验、仓位口径、手续费 —— 全是执行层，与模型判断无关
- "系统整体负期望" —— 真金白银的统计，与标签无关
- "手续费占毛亏 50-65%" —— 同上

## 6. 可选动作

1. **把候选集变成硬约束**：阶段一输出越出 constrain_worthy 的候选集时拒绝并重试。
   代价：重试增加 token；收益：标签可复现性提升，且可用本工具量化。
2. **多次采样投票**：同一根 K 线跑 3 次取众数。成本 x3，一致性预计升至 ~85%。
   适合用在"可交易信号"这一层，而不是每轮分析都跑。
3. **降低对细分类别的依赖**：策略只区分"趋势 / 非趋势"这类粗二分，不区分
   normal_channel 与 broad_channel。
4. **保持观察**：每次改动 prompt 或模型后重跑本工具，作为噪声地板。

## 7. 复现

    python tools/variance_baseline.py <records/pending 下的文件名> 5 trimmed
    # 可选第 4 参数: 输出 json 路径

注意：运行期间出现过一次 503 platform_busy（重试后成功），说明 provider 端
不稳定本身也会引入方差，解读时不要把 API 抖动误当成模型随机性。
