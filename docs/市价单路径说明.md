## 2. 下市价单要满足的条件（四层，缺一不可）

### ① 路由层 —— `pa_agent/ai/decision_nodes.py`

| 条件 | 位置 |
|---|---|
| `cycle_position == "spike"` —— **唯一**把 candidate 默认设成市价单的周期 | `:1514-1525` |
| §10.3 判「是」（交易者方程通过），否则直接 `return []` | `:1553` |
| §14 未触犯 | `:1559` |
| 模型自己写 `order_type="市价单"` + 四价齐全 → 保留该选择 | `:1589-1594` |
| spike 已衰竭（`spike_stage ∈ ending/pullback/channel`）且模型写突破单 + 有 `entry_basis_*` → 改回突破单 | `:1623-1631` |
| ⚠️ 模型若写限价单且 §10.3=是 → candidate 被**覆盖**为限价单 | `:1583-1588` |

### ② 提示词硬规则 —— `pa_agent/ai/prompt_assembler.py:572`

```text
市价单 = 基于当前已收盘棒立即入场，不存在「等待触发」状态
  entry_bar.bar    必须是具体 K 序号（通常 K1），不能 null
  strength         strong 或 weak（不能 null）
  freshness        fresh（禁止 pending）
  follow_through   true
```

### ③ 校验层

| 规则 | 位置 |
|---|---|
| `entry_bar.bar` 为空（挂单态）时禁止市价单 | `json_validator.py:1137` |
| `signal_bar` 的 K 序号必须 > `entry_bar` 的 K 序号 | `json_validator.py:1139` |
| `neutral` 诊断时禁止任何方向单 | `prompt_assembler.py:446` |

### ④ 执行层 —— `execute_market_signal`（`binance_usdm_testnet.py`）

- 环境：`enabled=true`、`emergency_stop=false`、`dry_run=false`
- `order_type ∈ {市价单, 限价单, 突破单}`（`:1134`）。**市价单没有独立开关** ——
  限价单受 `limit_order_enabled`、突破单受 `breakout_order_enabled`，市价单无对应键

- 无重复持仓、冷却 30min、日亏上限、notional 上限

- **方向闸门 G1/G2 不适用市价单** —— `direction_gates.py:87` 只处理「限价单/突破单」

## 3. 为什么实际是 0（三个倾向叠加）

1. **策略文件明确「优先限价单」** —— `prompt_engineering/上涨通道交易策略.txt:113`、
   `prompt_engineering/下跌通道交易策略.txt:123` 都写「优先限价单在前一棒低点/反弹位挂单」。
2. **市价单门槛比限价单高** —— 要求 `freshness=fresh` 且入场棒是具体 K1；
   限价单允许 `pending` + `signal_bar.bar=null`（§9.0P 计划型）。
3. **spike 占比极低** —— 132/5542 = 2.4%，且其中 83% 模型自己就观望。

再叠加当前 `decision_stance="conservative"`（偏保守立场），市价单倾向被进一步压低。

⇒ **0 条不是 bug，是设计 + 文件倾向的合成结果。**

## 4. 若要让市价单真正出现（三条路，按代价排序）

| 选项 | 做法 | 代价 |
|---|---|---|
| A 放宽路由入口 | 把 `trending_tr` 的 candidate 从「突破单」改成「市价单/突破单二选一」 | 改判定，需回放验证；`trending_tr` 是已知负期望段 |
| B 改策略文件措辞 | spike/趋势延续段落改成「可不回踩、直接市价」，并补 `entry_bar=fresh` 硬要求 | prompt 改动，可用 k2 A/B 管线做对照 |
| C 不动 | 承认市价单在当前设计里是备用路径 | 零成本 |

**建议先不动。** `docs/被拦订单反事实分析.md` §5 显示 `trending_tr_block` 是全闸门栈里
唯一被两个口径一致支持的负期望拦因（口径 A −0.96 / 口径 B −6.77）——在它上面加市价单，
等于放大已知负期望。

## 5. 边界

- 「0 条」覆盖全部落盘记录（2026-08-07 起），但 `order_type` 字段在早期记录里为 null（1045 条），
  那段时间是否出现过市价单**无法从记录判断**；不过那批记录里也没有任何订单类型，
  说明当时根本没走到下单类型判定。
- 本文只描述**代码允许什么**与**历史发生了什么**，不构成对市价单优劣的判断。

## 6. 已实施：市价单解禁的最小集合（2026-09-20）

用户指令「启用市价单」。改动立场：**不动「追单」禁令**（那些有据），只做两件事 ——
补上涨通道缺失的对称许可，并把「禁止市价」的表述收窄为「禁止**追单式**市价」。

| # | 文件 | 改动 |
|---|---|---|
| 1 | `prompt_engineering/提示词大纲_人设与思维方式.txt`（硬禁令 2） | 增补：被禁的是**追单式**市价（追尖峰/追第一根突破棒/高潮后追）；**趋势线或结构位被触碰、且出现拒绝信号 K 之后**，用当根收盘价顺 direction 市价入场是**允许**的；须填 `entry_bar.bar`、`freshness=fresh`、`follow_through=true` |
| 2 | `prompt_engineering/上涨通道交易策略.txt`（窄通道交易方法） | 补对称条款：**趋势线/通道下轨被触碰后的第一根阳线收盘时市价买入**，与下跌通道「策略三：趋势线反弹卖出」（原第 71 行）对称 |
| 3 | `pa_agent/config/settings.py` | 新增 `market_order_enabled: bool = True`（与 `limit_order_enabled` / `breakout_order_enabled` 对称） |
| 4 | `pa_agent/trading/binance_usdm_testnet.py` | 执行层尊重该开关：关闭时返回 `skipped: Market order automation disabled` |
| 5 | `config/settings.example.json` | 两个配置节都补 `market_order_enabled: true` |

**为什么以「对称」为落点**：`下跌通道交易策略.txt:71` 本来就写着「或在趋势线被触碰后的第一根阴线收盘时市价卖出」——
市价单从来不是被全面禁用，是**只在空侧写了一条、多侧没写**，加上十几处「追单」禁令读起来像「市价=禁」。
本次改动把这个不对称补齐，并显式区分「追单式」与「触碰确认后」。

**保留的禁令**（一字未动）：SCS 尖峰追单、市价追第一根突破棒、高潮后追原方向、
`极速上涨/下跌` 与 `二元决策` 里的全部追单禁令。

**生效**：`market_order_enabled` 是 `settings.json` 键，需重启监控进程才加载；
prompt 文件是每次组装时 `read_text` 读盘（`prompt_assembler.py:1058`），改后下一轮即生效。

**风险与边界**：
- 这是**策略层改动**，会改变模型可能输出的单类型，因此 `GATE_START` 需同步前移（不跨配置混样本）。
- 「上涨通道下轨触碰后第一根阳线市价买入」这条**没有历史样本可验证** —— 历史 0 条市价单，
  回放也无法模拟（回放只吃落盘决策）。它的效果只能靠上线后的样本外数据判断。
- 方向闸门 G1/G2 **不覆盖市价单**（`direction_gates.py:87` 只处理限价单/突破单），
  也就是说市价单路径没有「追单/反手」的程序化护栏 —— 这正是本次刻意保留提示词禁令的原因。
