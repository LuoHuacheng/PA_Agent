# 逆势过滤参数评估

日期：2026-09-10　样本：2026-08-07 — 2026-09-10

## 1. 为什么要做

方向评估（tools/direction_audit.py）显示模型的方向判断是系统性负超额：

    未来 8 根 K 线:  样本 1276   命中 42.5%   基线(多数类) 53.1%   超额 -10.6 个百分点

按 7 天日线趋势对齐后分化明显：

    顺势  477 笔 37%   超额  -2.5
    逆势  257 笔 20%   超额 -28.8
    中性  542 笔 42%   超额  -9.0

所以"拦住逆势单"是当前唯一有硬数据支撑的改动（详见 direction_audit 输出）。

## 2. 数据与方法

影子回放（tools/shadow_replay.py）把 records/pending 里的决策与本地 K 线重演成
502 个计划单，按当前仓位口径（risk_per_trade_usdt = 4U）统一换算，模拟成交 242 笔。
该模拟器已在 73 笔真实成交上校准：净差中位 +0.011U。

逆势判定与执行层同源：取决策时刻往回 trend_lookback_days(7) 根日线的涨跌幅；
|涨跌| <= trend_neutral_band_pct 视为无趋势（不拦），否则方向与趋势相反即为逆势。

复算命令：

    python tools/shadow_replay.py --replay --days 45 --variants --trend-days 7 --trend-neutral 1,1.5,2,3,5

禁逆势 1.0% 与它效果相当，但多保留 7% 的交易，因为它不拦顺势做空。

## 4. 决策

trend_neutral_band_pct: 3.0 -> 1.0（同时对齐 settings.py 默认值与 settings.example.json）

理由：样本只减 13%（200 到 173），胜率 +4 个百分点，45 天口径净亏改善 122U，
拦掉的是超额最差的一档。

## 5. 预期与复核

重启监控后跑 1-2 周，用下面两条命令复核：

    python tools/direction_audit.py --days 7 --trend-days 7 --trend-neutral 1,3
    python tools/shadow_replay.py --replay --days 7 --variants --trend-days 7 --trend-neutral 1

要看的变化：

    模型 bearish 占比   改前 43%
    逆势单占比          应接近 0（被 counter_trend_block 拦掉）

如果 bearish 占比仍高于 40%，说明"日线趋势注入 prompt"这一层没起作用，只能靠执行层硬拦。

## 6. 注意事项

- 行情依赖：样本期是 30 天中位 +30% 的单边牛市，逆势单基本等同于做空。
  行情转熊后拦截方向会翻面，规则本身仍然成立（它比对的是趋势，不是固定方向）。
- 所有档位的每笔期望仍然是负的（最好一档 -1.33U/笔）。这次调整是"少亏"，不是"转正"。
- date 变更窗口：日线趋势只在本地日切换时重算，重启不是必需但会让新参数立即生效。
